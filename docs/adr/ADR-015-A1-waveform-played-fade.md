# ADR-015-A1（提案）：波形已播放区改为整体降低不透明度

- 状态：**Accepted**（owner 批准：2026-11-16）
- 日期：2026-11-15
- 关联：ADR-015（波形进度条，已生效；本文件为其修订）、ADR-024（五套主题）

## 1. 冲突点

ADR-015 §5.3 / §9.5 规定：已播放区 `[0, x)` 用 `WaveformPlayedOverlayBrush` 覆盖一层
“面板底色 + 半透明”（深色 alpha ≈ 0.30、浅色 alpha ≈ 0.45），并明确“不要用乘 0.62 / 混 50% 灰”。

Owner 最新要求（2026-11-15）：**未播放区 100% 不透明度，已播放区淡到约 25–28% 不透明度**，
且三色带之间必须是分段不透明填色、不能出现半透明混色。覆盖层方案会让已播放区的三色带
与面板底色混合，色相被压暗、低/中/高三个频段的区分度下降，与新要求冲突。

按 AGENTS.md §1：先指出冲突条目，由 owner 裁决改代码还是改 ADR。本提案即“改 ADR”的裁决建议。

## 2. 决策（建议）

- 删除 `WaveformPlayedOverlayBrush`：主题字典令牌、`WaveformSeekBar` 的
  `PlayedOverlayBrushProperty` / `PlayedOverlayBrush` 属性、`Controls.xaml` 样式 setter 一并移除。
- 渲染改为按区域绘制几何、不做颜色混合：
  1. 未播放区 `[playhead, width)`：`PushClip` 该区域，低/中/高三条色带按 100% 不透明度绘制；
  2. 已播放区 `[0, playhead)`：`PushClip` 该区域，`PushOpacity(0.26)` 后按同样顺序绘制三条色带；
  3. 播放头、悬停预览、聚焦环、未分析区提示线顺序不变，仍绘制在色带之上。
- 常量 `PlayedOpacity = 0.26` 放在控件内部（不新增主题令牌），落在 owner 要求的 25–28% 区间中部。
  若以后需要按主题微调，再升级为令牌。
- 复核结论：`PlayedOverlayBrush` 没有其他 XAML/C# 消费方，删除是内部 API 变更，不影响配置 schema。

## 3. 影响文档

- ADR-015 §5.3 令牌表：删除 `WaveformPlayedOverlayBrush` 行；补充“已播放区由几何+不透明度实现，
  不用覆盖色”。
- ADR-015 §6 依赖属性清单：删除 `PlayedOverlayBrush`。
- ADR-015 §9.5 渲染顺序：把“已播放区覆盖色”改为“按区域 clip + PushOpacity(0.26) 绘制三色带”。
- ADR-015 §7/§9.2 中“主题切换需让几何缓存失效”的表述保持，配色仍来自主题令牌
  （`WaveformLowBrush` / `MidBrush` / `HighBrush` / `TrackBackgroundBrush` / `PlayheadBrush`）。

## 4. 备选方案

1. 保留覆盖层，仅把 alpha 调到 0.75（等效 25% 可见）：仍是与面板底色的混合，浅色主题会发灰，
   且不同主题面板色不同导致“已播放区”观感不一致，否决。
2. 已播放区改成灰色单色带：丢失三色带信息，用户明确要求保留三色带，否决。
3. 已播放区降低饱和度而不是不透明度：WPF 几何绘制需要逐色换刷子，实现与验证成本高，
   且“淡出”语义用不透明度更直接，否决。

## 5. 验证

- 5 套主题的波形模式截图（`--waveform <file> <png>`，定位 40%）：已播放区约为未播放区的 26% 不透明度，
  三色带在两侧都保持色相分离；浅色主题不再出现“发灰”。
- 未播放区与轨道底色对比保持不变；播放头在已播放区上仍清晰可辨。
