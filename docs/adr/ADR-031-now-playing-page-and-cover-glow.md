# ADR-031：「正在播放」页与封面柔光取色

- 状态：Accepted（2026-11-22 owner 批准）
- 日期：2026-11-22
- 相关：ADR-003（封面缓存与内存上限）、ADR-005（每个播放列表独立布局）、ADR-023（右栏可视化）、ADR-024（五套主题体系）；设计参考 `docs/ref/now_playing.html`

## 1. 背景

当前主窗口只有「播放列表」页，正在播放的信息集中在右栏专辑面板（封面 + 标题 + 频谱）。owner 要求参考 `docs/ref/now_playing.html` 新增一个与播放列表页**平行**的「正在播放」页，用顶栏 TAB 切换：

- 新页右侧列表只显示「播放列表」，不再提供「同专辑」切换；
- 列表顺序必须与切换前的播放列表页顺序一致（也就是当前的播放顺序），但这页不分组、不提供顺序调整；
- 封面柔光要按**当前播放曲目的封面**实时计算颜色（不是固定色 / 设计稿里的演示色）。

## 2. 调研结论（2026-11-21）

同类软件分两派：

| 做法 | 代表 | 结论 |
| --- | --- | --- |
| 模糊 / 扭曲封面当背景 | Apple Music（4 层封面 + twist shader + Kawase blur）、Poweramp、foobar2000、多数桌面播放器 | 实现简单但持续占 GPU，且与「纯白极简」主题不协调 |
| 量化取色 + 目标打分 | AndroidX Palette、Material You、Spotify(Colorfy)、ColorThief | 色彩可控、开销低、可随主题归一化，适合本项目 |

采用第二派。参考实现的关键参数：

- AndroidX Palette：图缩到约 112² 面积；HSL 过滤近黑（L≤0.05）/近白（L≥0.95）；5-bit RGB 直方图（32768 桶）中位切分 16 色；打分 `0.24·饱和度接近 + 0.52·亮度接近 + 0.24·像素占比`，Vibrant 目标 L 0.5 / S 1.0、Light Vibrant L 0.74。
- Material You：HCT（CAM16 色相/彩度 + CIELAB L\*）空间，Wu 量化 + WSMeans k-means，Score 权重 `占比×100×0.7 + (chroma−48)×(0.1 或 0.3)`。
- Spotify(Colorfy 逆向)：100×100、k-means k=8、Hasler-Süsstrunk colorfulness 选最大，低于阈值回退 `#E6E6E6`。
- Windows 11 Mica：不处理封面；壁纸只采样一次并与主题色合成，透明度关闭 / 节电 / 老系统回退纯色。

对本项目最有价值的三点：**OKLab/OKLCH 做亮度与彩度归一化**、**按主题目标区间裁剪**、**透明 PNG 先解预乘并过滤低 alpha**。

## 3. 决策

### 3.1 页面结构

- 顶栏新增页面切换器（「播放列表」/「正在播放」两个 TAB），内容是同一窗口内的两个平行页；切换不重建播放器，当前播放不中断。
- 新页面激活时收起左侧资料库栏与右侧专辑面板（保存 / 恢复用户原来的宽度），退出时还原；两个 GridSplitter 同步隐藏。
- 新页布局：左侧封面 + 元数据 + 标签卡片 + 频谱（复用现有 `SpectrumView`），右侧 344 DIP 为当前播放列表。
- 右侧列表数据来自当前列表视图的顺序快照（分组开启时取分组视图顺序，即播放顺序），**不分组、不拖拽排序、不提供「同专辑」**；点击 / 双击行播放，定位按钮把当前行滚到视口中央。
- 尺寸自适应：宽窗口封面 300 DIP；窗口变窄退 250、变矮退 210，高度不足 520 DIP 时收起标签卡片，保证频谱始终可见。

### 3.2 柔光算法（Core 纯逻辑，可单测）

新增 `Core/Models/CoverPalette.cs`、`Core/Services/OklchColorMath.cs`、`CoverPaletteExtractor.cs`、`CoverPaletteThemeMapper.cs`：

1. 输入 App 层已 Freeze 的封面 `BitmapSource`，转 BGRA32 后 `CopyPixels`（不用 `GetPixel`），长边缩到 64 采样。
2. 过滤：alpha<128、OKLab L≤0.16（近黑）、L≥0.95（近白）、C<0.012（近灰）丢弃；有效彩色样本 <32 或彩色占比<2% 判定失败。
3. 量化：5-bit RGB 直方图 + 中位切分到 16 箱，箱内按像素加权平均 L / (C·cosH) / (C·sinH)。
4. 打分：`0.30·占比 + 0.45·彩度 + 0.25·亮度接近目标`（彩度权重高于 Palette，因为最终只以 25%/13% 透明度叠加在浅底上）。
5. 主色目标 C≥0.045、L∈[0.34,0.80]、占比≥1.5%；次色要求与主色色相距离≥25°，缺失时派生（H+18°、C×0.65、L+0.06）。
6. 主题映射：浅色主题主色 L 0.52–0.66 / C 0.07–0.15，次色 L 0.56–0.70 / C 0.05–0.11；深色主题 L 0.62–0.78 / C 0.06–0.13 等；越界用 OKLCH 降彩度（每步 ×0.92）而不是直接 clip RGB。
7. 无封面 / 解码失败 / 近乎灰度：回退当前主题强调色派生（`UsedFallback` 标记），而不是硬取灰色。

### 3.3 渲染（App 层）

- 新增 `Views/Controls/CoverGlow`：两层 `RadialGradientBrush`（`RelativeToBoundingBox`，圆心 16%,22% 与 48%,14%，半径约 0.55），每个 brush 5 个 stop、alpha=峰值·(1−r)²，末尾 stop 用同 RGB + A=0（避免 sRGB 插值发黑边）；只动透明度做 450 ms 交叉淡入，`SystemParameters.ClientAreaAnimation=false` 时直接切换；`IsHitTestVisible=false`。
- 峰值透明度做成主题令牌（`NowPlayingGlowPrimaryAlpha` / `SecondaryAlpha`）：Pure 0.25/0.13、Warm 0.22/0.11、Nordic 0.24/0.12、Midnight 0.30/0.17、Slate 0.28/0.16；五套主题字典同步新增。
- 新增 `Services/NowPlayingGlowService`：后台线程取色；原始调色板按「路径 + CoverKey + 修改戳 + 大小」缓存（LRU 96 条）；切主题只重做映射（<0.1 ms），不重新读图。

## 4. 后果

- 新增 1 个 Core 模型 + 3 个 Core 纯函数服务 + 15 个单元测试；App 层新增 1 个控件、1 个服务、1 个页面与对应视图模型状态。
- 五套主题各新增 2 个 `sys:Double` 令牌；主题切换后新页柔光会随主题重新归一化。
- 只在播放 / 切歌 / 切主题时计算一次颜色，不产生每帧开销；取色在后台线程，不阻塞 UI。
- 右侧列表顺序是快照：播放列表页排序 / 过滤 / 切源后会重建；页面本身不提供顺序修改入口。

## 5. 备选方案（未采用）

- **整图模糊封面**：GPU 持续开销、与纯白/纸感主题不协调，且设计稿是「柔光」不是「毛玻璃」。
- **固定 per-track 调色板（设计稿做法）**：需要人工维护颜色表，不是「实时按封面计算」，不与文件内容一致。
- **Material You HCT 全链路**：需要引入大型量化 / 色彩空间库与更多常量，收益不足以抵消复杂度；本方案用 OKLCH + 中位切分已满足需求。
- **在 XAML 里用 `ColorAnimation` 动画画刷**：WPF 对 `GradientStop.Color` 动画开销大且会每帧重建画刷，改用两层图层透明度交叉淡入。

## 6. 验收要点

- 顶部 TAB 可来回切换，切换播放列表页后左栏 / 专辑面板宽度恢复原值。
- 新页右侧列表顺序与切换前播放列表页一致、无分组、无拖拽排序。
- 不同封面的柔光颜色不同；深色主题下柔光可见；无封面时回退主题强调色。
- 窗口缩到最小尺寸（980×600）时封面、频谱、右侧列表不被裁切。
- `dotnet build` / 全量单测通过；发布版本在 `artifacts/publish/win-x64`，目录内不产生 `EchoGarageData`。
