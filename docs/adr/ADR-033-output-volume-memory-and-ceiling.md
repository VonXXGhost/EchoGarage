# ADR-033：按输出设备与模式记忆音量，并按模式设置音量上限

- 状态：已批准（Accepted，2026-11-22，owner）
- 日期：2026-11-22
- 关联：ADR-032（输出设备热插拔与“上次使用的设备”记忆）、ADR-009（WASAPI 音频管线）、ADR-012（测试静音约定）

## 背景

当前音量只有 `settings.json` 里的一个全局字段 `volume`：

- 切换输出设备（例如从扬声器切到耳机）不会带过去“这台设备上次的音量”，用户需要重新调；
- 共享 / 独占模式的合适音量通常不同（独占模式绕过系统混音器，同一百分比往往更响），
  目前两种模式共用一个值；
- 独占模式绕过系统音量限制后，最高增益不受系统音量保护，存在输出过高功率损伤设备或听力的风险；
  用户希望为**特定模式**调低音量上限，并约定“音量滑块的 100% 即该上限”，从而在受限范围内获得
  更精确的调节精度。

用户需求（原文要点）：音量设置随输出设备记忆、切换时自动调整、共享 / 独占模式记忆独立；新增按模式的
音量上限，滑块的 100% 映射到上限，用于在独占模式下限制最大输出功率。

## 决策

1. **数据模型**（`Core/Models/AppSettings.cs` + 新文件 `Core/Models/OutputVolume.cs`）：
   - `Volume`（`double`，0–1）保留为**全局回落音量**，语义不变，旧配置无需迁移；
   - 新增 `DeviceVolumes`（`Dictionary<string, OutputDeviceVolume>`）：按输出端点 ID 分别记住
     `Shared` / `Exclusive` 两个 `double?` 显示音量，`null` 表示该模式无记忆；
   - 新增 `VolumeCeilings`（`OutputVolumeCeilings { double Shared = 1.0; double Exclusive = 1.0; }`）：
     按模式配置的音量上限（0–1）；
   - 不提升 `SchemaVersion`：所有新字段都有合理默认值，旧 `settings.json` 读入后行为与之前一致。
2. **音量记忆的键 = 当前实际输出端点 ID + 模式**：
   - 用播放器实际输出的设备（`SelectedDevice.Id`）而不是“用户偏好 ID”。这样即使用户选择
     “跟随系统默认设备”，不同默认设备（扬声器 / 蓝牙耳机 / HDMI）也各自拥有音量记忆；
   - 设备 ID 匹配忽略大小写；条目上限 32 个（长期插拔不会让配置无限增长），超出后不再新增；
   - 没有记忆时回落到全局 `Volume`（旧用户首次升级后的音量保持原样）。
3. **实际增益 = 显示音量 × 该模式上限**（`Core/Services/OutputVolumeResolver`）：
   - 音量滑块仍显示 0–100%，但 100% 代表“该模式的上限”，因此显示值不变时实际输出 = 显示值 × 上限；
   - 上限范围 5%–100%（下限 5% 防止上限被拖到 0 后完全无声且无法调回）；非有限值回退 100%；
   - 静音仍然把增益置 0，但不改动记住的显示音量；取消静音恢复“显示音量 × 上限”。
4. **记忆写入时机**：用户拖动音量滑块 / 滚轮调节时，立即写“当前设备 + 当前模式”的记忆并同步更新
   全局回落音量；切换设备或模式时读取对应记忆并刷新滑块显示。程序退出、导入配置、设备刷新都不会
   用当前状态覆盖记忆（与 ADR-032“偏好只由显式操作写入”一致）。
5. **启动与导入**：
   - `AppHost.InitializeAsync` 用“启动时的设备 ID + 模式”解析显示音量并乘上限后写入
     `IAudioPlayer.Volume`，并记录诊断日志 `Initial output volume: ... display × ceiling = gain`；
   - 导入配置时同步 `Volume` / `DeviceVolumes` / `VolumeCeilings` 并强制重新加载当前上下文的音量。
6. **设置界面**（`SettingsWindow` 播放页）：
   - 在“音频输出”区域新增“音量上限（按模式）”：共享 / 独占两行 5–100% 滑块 + 百分比读数；
   - 底部主界面音量滑块增加悬停提示“音量 X% · 某模式音量上限 Y%”，让“100% = 上限”可见；
   - 设置页与主界面共用同一个 `MainViewModel`，上限改动即时生效并随配置保存。
7. **规范化**（`JsonSettingsService.Normalize`）：上限夹到 5%–100%；设备记忆去空白键、去无效值、
   音量夹到 0–1、键去重（忽略大小写）、限 32 条；不新增文件、不新增依赖。

## 理由

- 按“实际端点 + 模式”记忆比“按偏好 ID”更符合用户直觉：同一副耳机在共享 / 独占下的音量都应记住，
  而“跟随默认设备”时每台默认设备也应各自有记忆。
- “滑块 100% = 上限”的映射让上限成为用户可理解的安全边界，同时保留滑块的调节精度：
  例如独占上限设为 30% 时，滑块 50% 实际输出 15%，比直接压到 15% 更容易精细调节。
- 上限按模式全局设置而非按设备：需求明确是“在特定模式下”限制功率，避免再引入一层
  “设备 × 模式”的上限矩阵；若未来确有需要可再加一层覆盖值。
- 全局 `Volume` 保留为回落值，保证旧配置与旧行为兼容，避免迁移失败导致用户音量突变。
- 纯逻辑放 `Core/Services` 用 xUnit 覆盖（解析 / 记忆 upsert / 增益乘法 / 规范化），
  与仓库“业务规则必须有单元测试”的约定一致。

## 后果

- `settings.json` 新增 `deviceVolumes`（可能为 `{}`）与 `volumeCeilings` 两个字段；旧版本读取新配置时
  会忽略未知字段，新版本读取旧配置时使用默认值，双向兼容。
- 用户可见行为变化：音量滑块 100% 不再必然等于播放器满增益（上限默认 100%，因此调整上限前行为不变）；
  切换设备 / 模式会自动恢复该组合上次的显示音量；设置页新增两个滑块。
- 独占模式下若用户把上限调低，实际最大输出被限制；共享模式同样受上限约束（用户可保持 100%）。
- 与 ADR-032 交互：设备缺失回退默认设备时，音量为“回退设备 + 当前模式”的记忆；偏好设备恢复后
  切回偏好设备并恢复它自己的音量记忆。
- 无数据库 / 媒体库变更，不涉及 `PRAGMA user_version`；不新增第三方依赖。

## 备选方案

- **把音量和上限都放到 `OutputDeviceVolume` 里按设备保存**：上限会变成“设备 × 模式”矩阵，
  配置膨胀且与需求（按模式限制功率）不符；故采用模式级上限。
- **滑块直接显示实际增益（0–上限）**：调节精度下降，且用户无法一眼看出安全上限，否定。
- **用系统音量 API 限制共享模式最大值**：独占模式根本不经过系统混音器，无法覆盖需求中的主要风险场景。
- **沿用单一全局音量、切换设备时不变**：不满足“随设备记忆、切换自动调整”的需求。
- **升级 `SchemaVersion` 做显式迁移**：新字段均有安全默认值，显式迁移收益低、风险更高，放弃。

## 手动验证步骤

1. 构建并运行测试：`dotnet build EchoGarage.sln`；
   `dotnet build tests/EchoGarage.Tests` 后运行 `EchoGarage.Tests.exe`，
   `OutputVolumeResolverTests` 与 `SettingsTests` 覆盖解析 / 记忆 / 增益 / 规范化规则。
2. 用独立数据目录（`ECHOGARAGE_DATA_DIR`）写一份 `settings.json`：`volume` 0.75、
   `volumeCeilings` `{ "shared": 0.5, "exclusive": 0.3 }`、
   `deviceVolumes` 为当前输出设备的 demo 端点 ID、其 `shared` 0.8 / `exclusive` 0.4；
   启动发布版后日志应出现 `Initial output volume: 80% display × 50% Shared ceiling = gain 0.4`，
   主界面音量显示 80%，设置页上限显示共享 50% / 独占 30%。
3. 在界面把音量拖到 50%（共享），退出后重开：音量应保持 50%；切到独占模式应恢复 40%；
   切回共享应恢复 50%。
4. 修改共享上限为 60%：实际输出应为 50% × 60% = 30%（可结合日志
   `Applied output volume: display=... ceiling=... gain=...` 核对）。
5. 静音 / 取消静音：静音时增益 0，取消后恢复 显示音量 × 上限，且不改变记住的显示音量。
6. 运行验证时保持静音或把上限调低，避免真实播放造成过大音量（ADR-012）。
