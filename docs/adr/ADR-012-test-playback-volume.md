# ADR-012：测试运行时的输出音量

- 状态：已批准（Accepted，2026-11-12，owner）
- 日期：2026-11-12

## 背景

EchoGarage 的很多测试需要真实启动程序并播放音频（播放起止、切歌、跳转、自动居中、封面与状态栏刷新、自动化 UI 交互等）。
开发用的电脑同时也是 owner 日常使用的电脑，测试时若有声音以正常音量外放，会突然打断 owner 的工作或休息。

## 决策

1. **凡实际运行程序并播放音频的测试，除调试音量 / 静音相关功能外，必须先把输出音量调到尽可能小，优先静音。**
   - 首选：音量 0（无声）。
   - 音量 0 若影响待测路径（例如需要验证音量条 / 静音图标联动），退而使用用户听不到的最低档（≤1%）。
2. 测试使用独立的 `ECHOGARAGE_DATA_DIR` 副本运行，不得为降低音量而修改 owner 日常使用的 `settings.json`；测试结束后不留下被改动的个人配置。
3. 音量 / 静音相关功能的测试必须显式说明原因，并在测试结束后恢复原音量与静音状态。
4. 若某类验证必须依赖听感（例如确认实际输出内容），先征得 owner 同意，并在其方便的时间进行。

## 理由

- 播放状态、`CurrentRow`、进度、WASAPI 音量链、UI 刷新等行为不依赖可听音量，静音不影响绝大多数回归验证。
- 独立数据目录副本既保护 owner 的配置，也避免测试相互影响（与 ADR-006 的便携数据根一致）。

## 后果

- 音量 / 静音相关测试需要单独说明，且必须做状态恢复，测试步骤略多。
- 静音下无法做听感判断，需用日志、状态与截图断言替代。

## 备选方案

- 把系统音量调低：影响 owner 其它程序，且是全局副作用，不如在应用内静音。
- 切换到虚拟音频设备：会改变 WASAPI 输出路径，覆盖不到真实设备行为，且配置成本高。
