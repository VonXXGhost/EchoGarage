# ADR-011：按专辑分组时的封面尺寸纳入播放列表布局

- 状态：提案（待 owner 批准）
- 日期：2026-11-10
- 关联：ADR-005（播放列表显示格式）
- 适用范围：`PlaylistViewLayout` 序列化、`MainWindow` 列构建、专辑分组头

## 背景

按专辑分组时，分组头封面固定为 96px，行内封面列被强制成 96px 的对齐槽位，用户拖动
“封面”列宽会被立即改回 96，因此无法调整封面大小。另一方面，取消分组时同一列宽又用于
逐行小封面（图片固定 24px），两种模式的列宽语义不同。

## 决定

1. `PlaylistViewLayout` 新增 `GroupCoverSize`（double，默认 96，范围 48–320），随播放列表
   布局一起序列化到 `settings.json` / `playlist.ViewLayoutJson`；旧 JSON 没有该字段时按 96 处理。
2. 分组模式下，“封面”列宽就是 `GroupCoverSize`：拖动表头右缘即可实时改变分组头封面大小，
   列宽范围也限制为 48–320。该值不会写回普通模式下的封面列宽，取消分组后逐行封面仍用原列宽。
3. 列与布局对话框只编辑列；`GroupCoverSize` 原样透传，应用预设时也保留当前值（预设不包含封面尺寸）。
4. 拖动结束后 600ms 防抖持久化一次；关闭窗口 / 切换播放列表仍走原有布局保存路径。
5. 分组头封面单独按 512px 解码（`TrackRowViewModel.GroupCoverImage`），在最大 320 DIP、
   150% DPI 下仍清晰；分组头虚拟化卸载时释放该引用，避免滚动过所有专辑后常驻大图。

## 理由

- 用户对“封面列宽调整分组头封面”有直接预期；把该尺寸作为布局的一部分，和 ADR-005 的
  “每个播放列表独立记忆显示格式”一致。
- 不引入全局设置，也不破坏普通模式的逐行封面列宽。
- 用布局内字段而非数据库列，旧数据无需迁移（缺失即默认值）。

## 备选方案

- **直接复用封面列宽**：取消分组后行内封面列会变成 48–320 的宽槽，行高仍 32px，观感差。
- **全局设置项**：所有播放列表共用一个封面尺寸，与“每个播放列表独立布局”不一致。
- **固定 96px 不可调**：即现状，用户已明确要求可调。

## 后果

- 布局 JSON 多一个字段；导出/导入配置会带上它（属于显示配置，符合 ADR-006）。
- 分组头封面解码从 128px 提升到 512px（仅可见分组），内存由虚拟化卸载控制。
- 顺带修复一个启动期布局被覆盖的缺陷：首次选择来源时窗口尚未建列，原逻辑会把内存里的
  默认布局写回设置，导致自定义列宽 / 排序在重启后丢失；现在视图没有列时跳过持久化。
